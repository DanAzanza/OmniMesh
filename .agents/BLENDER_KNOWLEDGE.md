# Blender Platform & Runtime Knowledge Base

> **Scope**: Universally applicable to Blender 4.2+, 5.0+, and 5.2 LTS add-on development, headless automation, and C-API bindings.
> **Rule**: Persistent memory strictly for **non-obvious runtime quirks, C-API memory management, RNA lifecycle traps, and fake-bpy stub defects** that cannot be inferred from reading standard Python documentation or type annotations alone.

---

## 1. Blender 5.0+ & 5.2 LTS Shading, Enums & Rendering

### 1.1 Shading, Enums & EEVEE Next
* **EEVEE Next Shading**: `material.shadow_method` does not exist and `mat.blend_method = 'CLIP'` is dead code. Transparency for cutouts/impostors strictly requires `mat.surface_render_method = 'DITHERED'` (or `'BLENDED'`).
* **glTF 2.0 Export Format**: Use `export_format='GLTF_SEPARATE'` for `.gltf` + `.bin` export in Blender 5.2 LTS (`GLTF_EMBEDDED` was deprecated).
* **`DATA_TRANSFER` Loop Mapping & `ray_radius` BVH Traversal Trap**: `dt_mod.loop_mapping = 'POLYINTERP_LNORPROJ'` is the only valid projected normal loop mapping enum in Blender 5.2 LTS (`POLYINTERP_NEAREST_CORNER` was removed). Always keep `dt_mod.ray_radius = 0.0` and leave `use_max_distance = False`: setting a non-zero `ray_radius` forces Blender's `BLI_bvhtree_ray_cast` to perform cylindrical radius overlap checks across the source BVH for every target loop ($O(N \cdot K)$ instead of $O(N \log M)$), degrading 100k-triangle normal reprojection from ~1.2s to ~14.8s.
* **Native `mathutils.geometry.delaunay_2d_cdt` Return Length**: Unlike standard 2D triangulation routines returning 3 items, Blender's native C-routine returns a 6-item tuple: `(verts, edges, faces, orig_verts, orig_edges, orig_faces)`.

### 1.2 Cycles GPU & Headless Rendering Invariants
* **Cycles GPU Device Detection (Blender 5.0+)**: Assigning `cpref.compute_device_type = backend` does NOT automatically refresh `cpref.devices`. Calling `cpref.get_devices()` is mandatory before iterating devices or setting `d.use = True`.
* **Headless Impostor Bake Acceleration**: Software OpenGL/Vulkan via Mesa `llvmpipe` on CPU cloud runners stalls on shader compilation (>25 min for 192 views). Headless bake scenes (`bpy.app.background == True`) must prioritize CPU `CYCLES` with `samples = 1` and SIMD BVH ray-tracing (~12s).
* **AgX / Filmic Color Management on Data Passes**: In Blender 5.0+, the default `AgX` view transform tone-maps linear vectors into non-linear sRGB (crushing normal blue channels from $1.0$ down to $\sim 0.3$). Ephemeral bake scenes must set `bake_scene.view_settings.view_transform = "Raw"` for data passes (Normal, Depth, ORM) and `"Standard"` for BaseColor.

## 2. Collection & Object RNA Lifecycle

* **RNA Pointer Invalidation on Collection Purge**: Storing a collection reference before unlinking/removing collections invalidates the C struct pointer (`ReferenceError: StructRNA of type Collection has been removed`). Purges and deletions must strictly precede retrieving or creating target collections.
* **View Layer Collection Exclusion (`LayerCollectionGuard`)**: Evaluating modifiers, depsgraphs, or transferring normals fails or outputs empty meshes when the target collection is excluded (`layer_collection.exclude = True`). All multi-collection processing must be wrapped in `LayerCollectionGuard`.
* **Modifier Execution Context under `temp_override`**: In Blender 5.2+, applying modifiers on objects inside collections without `temp_override(active_object=lod_obj, object=lod_obj, selected_objects=[lod_obj])` fails or causes view layer selection lockups.
* **Evaluated Depsgraph & Matrix Evaluation Latency (`context.view_layer.update()`)**: Assigning `obj.location`, `rotation_euler`, or `scale` in Blender Python mutates local RNA attributes immediately, but `obj.matrix_world` does NOT update synchronously for relative transformations (such as `parent.matrix_world.inverted() @ child.matrix_world`) until `context.view_layer.update()` is explicitly called prior to `context.evaluated_depsgraph_get()`. Omitting this update yields stale world matrices from the prior frame or initial state.
* **`bpy.context` Volatility in Headless & Batch Environments**: In headless Blender (`blender -b`), background workers, or batch execution, `bpy.context` is frequently incomplete (`view_layer`/`scene` is `None`, no active viewport). Domain logic must therefore never read global context in any form — neither `bpy.context` nor obfuscated lookups such as `getattr(bpy, "context", None)`. `context`/`scene` are required parameters injected by the operator or batch runner; a missing context is a caller bug and must raise, not fall back silently.
* **Copy-on-Write (CoW) Mesh Datablock Safety**: Applying modifiers or `transform_apply` on objects whose mesh datablock has multiple users (`obj.data.users > 1`, e.g. `Alt+D` duplicates) mutates shared geometry across all variants simultaneously. Always isolate: `if obj.data.users > 1: obj.data = obj.data.copy()`.
* **Blender RNA `ReferenceError` on Removed Objects**: Accessing attributes on an unlinked/removed RNA struct raises `ReferenceError: StructRNA of type Object has been removed`. Viewport draw handlers and event listeners must guard with `(ReferenceError, AttributeError)`.
* **Explicit `BlendData` Dependency Injection & Mock Container `__len__` Trap**:
  * **Zero `bpy.data` Invariant & Fail-Fast Database Contracts**: Domain modules (`core/`, `exporters/`) must never read or import global `bpy.data` directly or indirectly (`getattr(bpy, "data")`), because binding to global C-session database singletons breaks headless isolation and concurrency. All database queries and allocations must accept an explicit `blend_data: bpy.types.BlendData` parameter (resolved at the UI/presentation boundary via `context.blend_data`). Where database operations are mandatory, functions must fail-fast if `blend_data is None` (raising `ValueError`) rather than falling back silently to synthetic empty results (`return []`) or attempting obfuscated context recovery.
  * **Mock Container Truthiness / Length Trap (`if not container:`)**: When simulating Blender datablock pools (`BlendData.objects`, `BlendData.collections`, `BlendData.materials`, `BlendData.meshes`) with dictionary-backed mock containers in unit tests, Python evaluates `container.__len__()` for boolean expressions (`if not container:` or `if container:`). If the mock container is initially empty ($len = 0$), `bool(container)` evaluates to `False`! Precondition guards checking whether a datablock pool is available must strictly test `if container is None: return ...` rather than truthiness `if not container:`.

## 3. Blender RNA, UI & Extension Traps

* **Extension Directory Invariant (Blender 4.2+)**: User extensions reside strictly in `%APPDATA%\Blender Foundation\Blender\<ver>\extensions\user_default\<addon_id>` (`bl_ext.user_default.<addon_id>`). Copying files to legacy `scripts/addons/<addon_id>` will NOT update the live extension.
* **Blender Extension Wheel Dependency Isolation**: User extensions (`blender_manifest.toml`) do not bundle third-party PyPI wheels (such as Pillow/PIL). In live Blender installations, `Image` may be `None`. Texture packing, channel extraction, and resampling operations should provide pure-NumPy vectorized fallbacks (e.g. `resample_channel_bilinear_numpy`) rather than failing due to missing wheels.
* **Manifest Version Synchronization**: Blender 5.0+ Extensions rely exclusively on `blender_manifest.toml` (the legacy `bl_info` dictionary in `__init__.py` is deprecated/ignored). Keep `version` in `blender_manifest.toml` and `pyproject.toml` strictly synchronized.
* **Blend-Relative Paths (`//`)**: `bpy.props.StringProperty(subtype="FILE_PATH")` requires `options={"PATH_SUPPORTS_BLEND_RELATIVE"}` so Blender 5.x accepts `//` project-relative paths without emitting a `RuntimeWarning`.
* **Dynamic UI Class Unregistration & RNA Ghosting**: Hot-reloading modules fails if stale class references persist in Blender's C++/RNA registry. Clean unregistration must dynamically inspect `existing = getattr(bpy.types, cls.__name__, None)` and unregister `existing` before registering the reloaded class definition.
* **Live Operator Reloading & Dispatch Cache (`bpy.ops`)**: In an active interactive Blender session, calling `importlib.reload(module)` updates Python module attributes and bytecode, but Blender's internal C++ operator dispatch (`bpy.ops.<namespace>.<op_idname>`) caches function pointers and continues routing to the previously registered class. Operators must be explicitly unregistered via `bpy.utils.unregister_class(cls)` and re-registered via `bpy.utils.register_class(cls)` for code changes to take effect in the active runtime.
* **UIList Duplicate Registration & Zero-Height Collision Trap**: Failing to dynamically unregister reloaded `UIList` classes causes duplicate classes in `bpy.types.UIList.__subclasses__()`, rendering template lists with zero vertical height.
* **Ghost "Misc" Sidebar Tab Trap**: Any `Panel` declared with `bl_region_type = 'UI'` without an explicit `bl_category` defaults to `"Misc"`. Popovers must use `bl_region_type = 'HEADER'`. Collapsible subpanels (`bl_parent_id`) must explicitly declare their parent's `bl_category`.
* **Popover Horizontal Space Starvation**: In narrow N-Panels, pairing multiple text operator buttons alongside a popover button in an aligned row silently clips the gear icon off-screen. Action rows paired with a popover must hold at most ONE primary operator button.
* **RNA Mutation Ban in `Panel.draw()` (Runaway Redraw Loop)**: Never mutate RNA properties or sync data inside `draw()`. Writing to RNA triggers layout invalidation, forcing an infinite 60fps+ redraw loop at 100% CPU thread load. All sync logic belongs in `update` callbacks, operators, or `load_post` handlers.
* **`from __future__ import annotations` in Operators**: Writing `prop: Any = bpy.props.StringProperty(...)` stores the literal string `'Any'` in annotations, causing Blender to silently skip RNA registration and raise `TypeError: keyword unrecognized`. Use `prop: bpy.props.StringProperty(...)` directly.
* **Dummy `bpy.props` Fallback Invariant (`typing.get_type_hints` Crash)**: When operator modules are imported outside Blender or inspected via `typing.get_type_hints()` (e.g. for dynamic reflection or test suites in Python 3.10+), dummy property helper functions will crash if they return empty strings (`""` -> `SyntaxError: Forward reference must be an expression`) or `None` (`TypeError: 'NoneType' object is not callable`). Dummy property helpers (`StringProperty`, `BoolProperty`, etc.) must strictly reside inside `except ImportError:` (preventing RNA property clobbering inside Blender) AND must return `typing.Any`.
* **Dynamic `EnumProperty` Item Invalidation**: When deleting a custom item (such as a JSON preset), reassign active dynamic enum properties to a guaranteed fallback (e.g. `DEFAULT_PRESET_ID`) *before* disk deletion to prevent `bpy.rna WARNING current value matches no enum`.
* **RNA Property Leading Underscore Ban**: Properties on `bpy.types.PropertyGroup` MUST NOT start with an underscore (`_`), or registration of all subsequent properties in the class halts silently.
* **Operator Subclassing Invariant**: Never subclass a registered `bpy.types.Operator` class. Subclassing corrupts Blender's C++ RNA class table. Inherit directly from `bpy.types.Operator` and delegate via `bpy.ops`.
* **Blender C-RNA Dynamic Enum Assignment in Operators**: Assigning a dynamically added enum item immediately inside `execute()` can fail if the enum items tuple was cached at invocation. Wrap the assignment in a deferred timer (`bpy.app.timers.register(..., first_interval=0.005)`).
* **Blender Stubs Read-Only Setter Pattern (Pyright Strict vs Ruff B010)**: In `fake-bpy-module` stubs, several attributes (`Panel.layout`, `Modifier.object`, `Material.msfs_material_type`) are declared as read-only properties (`@property` without setter). Direct assignment (`panel.layout = mock_layout`) raises Pyright errors, while `setattr(panel, "layout", ...)` triggers Ruff `B010`. The unified pattern satisfying both strict type checkers and linters is `cast(Any, panel).layout = mock_layout`.
* **`fake-bpy-module` RenderSettings Engine & Cycles Stubs (Pyright vs Ruff B010)**: In `fake-bpy-module` stubs, `RenderSettings.engine` is typed strictly as `Literal['BLENDER_EEVEE']` (omitting `'CYCLES'`), and `scene.cycles` is typed as optional / `None`. Direct assignment `scene.render.engine = "CYCLES"` raises Pyright type errors (`reportAttributeAccessIssue`), while `setattr(scene.render, "engine", ...)` triggers Ruff linter rule `B010`. The unified pattern satisfying both strict type checkers and linters is `cast(Any, scene.render).engine = "CYCLES"` paired with a defensive check `cycles = getattr(scene, "cycles", None); if cycles: ...`.
* **`fake-bpy-module` Optionality Tightening (20261031+) & Safe Member Access**: In stubs released starting October 31, 2026, return types for `.copy()` on Objects and Meshes, `eval_obj.to_mesh()`, `armature.animation_data_create()`, `UILayout.operator()`, `mesh_data.uv_layers.new()`, and `NodeSocket.get()` / `.outputs.get()` were tightened to optional (`| None`). Under strict Pyright (`reportOptionalMemberAccess = true`), direct attribute chaining without non-null guards raises type errors. Always guard with `if lod_obj is None: return/continue`, `if uv_layer is not None:`, and `if op is not None:`. Furthermore, `scene.cycles` is typed as an optional add-on property and must be accessed via `getattr(scene, "cycles", None)` to prevent attribute errors.
* **`layout.box()` Row Hierarchy in Unit Tests**: When encapsulating UI controls inside grouped visual cards or container boxes (`box = layout.box()`), rows are instantiated via `box.row(align=True)`, not `layout.row()`. Unit tests and mock verification scripts asserting UI drawing structure must verify calls against `mock_layout.box` and the returned `mock_box.row` rather than expecting direct calls to `mock_layout.row`, preventing false-positive test assertion failures.
* **Operator Error Reporting in Python Calls**: Invoking a `bpy.ops.*` operator from Python that calls `self.report({"ERROR"}, ...)` and returns `{"CANCELLED"}` raises a `RuntimeError` in the Python caller rather than returning `{"CANCELLED"}`. Callers must handle `RuntimeError` when executing operators programmatically.
* **Dynamic Submodule Access on `bpy.ops` under Static Type Checking**: Add-on operator namespaces (`bpy.ops.lod_tool`, `bpy.ops.omnimesh`) exist only dynamically at runtime and are absent in `fake-bpy-module` stubs. In test suites and scripts, invoking them directly triggers Pyright `reportAttributeAccessIssue`. The approved pattern for test suites is `cast(Any, bpy.ops).lod_tool.<operator>`, while core production modules encapsulate dispatch via `core.compat`.

## 4. Skeletal Rigging, Transforms & BMesh Invariants

* **Rest-Pose Coordinate Inversion**: Transform bone-parented props into rest-pose local space before joining into a skinned character to prevent pose explosion.
* **Armature Rest-Pose Lock**: During decimation and normal data transfers, `armature.data.pose_position` MUST be set to `'REST'`, and restored afterwards.
* **Quaternion Sign Continuity Invariant ($\mathbf{q}_t \cdot \mathbf{q}_{t-1} < 0$)**: In 4D hyperspace, $\mathbf{q}$ and $-\mathbf{q}$ represent the identical spatial orientation ($360^\circ$ equivalence). If consecutive keyframes flip signs ($\mathbf{q}_t \cdot \mathbf{q}_{t-1} < 0$), spherical or linear interpolation (SLERP/LERP) traverses the long path around the hypersphere, causing visible $360^\circ$ spin flips. Negate $\mathbf{q}$ to $-\mathbf{q}$ when the dot product is negative prior to baking deform animations.
* **Vertex Group Index Shifting**: `obj.vertex_groups.remove(vg)` shifts indices of subsequent groups. Collect used group names first and purge by name.
* **GPU Weight Singularity Guard**: Stripping micro-weights ($< 0.01$) must never leave $\sum w = 0.0$ (causing GPU division-by-zero NaN shader crashes). Fall back to anchor bone (`1.0`).
* **`bpy.types.VertexGroup.add()` Parameter Quirk**: `vg.add(index, weight, type)` accepts a list of indices, but `weight` MUST be a single float (passing a list/array raises `TypeError`).
* **Shape Keys & Modifier Application (Fail-Fast QEM)**: In Blender C-API (`modifier.cc`), `bpy.ops.object.modifier_apply` strictly throws `RuntimeError: Modifier cannot be applied to a mesh with shape keys`. Derivative meshes must have shape keys purged before modifier decimation runs, while preserving shape keys on the hero source mesh (LOD0).
* **BMesh `bm.verts.index_update()` Requirement**: Newly created or bisected vertices keep `v.index == -1`. Attempting to populate vertex groups using `vg.add([v.index for v in ...])` without calling `bm.verts.index_update()` silently adds 0 vertices.
* **BMesh Dissolve & Boundary Pinning Index Invariance**: `bmesh.ops.dissolve_limit` mutates vertex indices. Planar limited dissolve must always run *before* boundary and UV seam tagging on the post-dissolve topology.
* **Spatial Bisect Seam Pinning vs. Natural Mesh Openings**: Tagging edges with `edge.is_boundary` mistakenly locks natural openings (eyes, sleeves). Seam locking must test vertex world coordinates against the explicit mathematical bisect plane ($|wco \cdot \vec{n} - d| < \epsilon$).
* **AABB Extent Bounding Sphere vs Centroid Bias**: Computing bounding sphere centers via point centroid $\frac{1}{N}\sum \mathbf{p}$ biases centers toward dense vertex clusters (cockpit controls, bevels), artificially inflating radius $r$ and decimation error. Centers must strictly derive from symmetric AABB extents $\frac{\min + \max}{2}$.
* **BMesh Topological Rollback and Recovery Contract**: During non-manifold edge or bowtie vertex splits in BMesh, `bmesh.ops` operations can fail midway. If new element creation fails, attempt restoring original vertices; if restoration succeeds, log a warning and preserve the original geometry safely; if restoration *also* fails, immediately raise a strongly typed exception fail-fast with actionable diagnostics rather than leaving deleted elements or corrupted holes in the mesh.
* **Fast C-Buffer Mesh Population**: For dense point clouds or high-resolution mesh generation, always allocate and populate `bpy.types.Mesh` via `mesh.vertices.add(n)` and `mesh.vertices.foreach_set("co", flat_float32_array)` rather than `mesh.from_pydata(points.tolist(), [], [])` to avoid multi-hundred-MB Python object allocations and garbage collector pressure.
* **Topological $O(1)$ Triangle Count Invariant ($n_{\text{tris}} = n_{\text{loops}} - 2 \cdot n_{\text{polys}}$)**: Iterating over polygons via `sum(len(p.vertices) - 2 for p in mesh.polygons)` is $O(N)$ and fails in `fake-bpy-module` stubs due to missing `__len__` on `bpy_prop_array`. For standard polygonal surface meshes, triangle counts derive strictly in $O(1)$ via the topological loop-poly invariant: $\text{Triangles} = n_{\text{loops}} - 2 \cdot n_{\text{polys}}$ (consolidated in `core.compat.count_mesh_triangles`).
* **Headless Quaternion Protocol under `TYPE_CHECKING`**: Outside Blender, `mathutils.Quaternion` is not available at runtime, and `Sequence[float]` does not expose `.w, .x, .y, .z`. To achieve strict type safety without introducing `: Any`, define a `QuaternionLike(Protocol)` declaring `w, x, y, z: float` under `if TYPE_CHECKING:` and narrow via `cast("QuaternionLike", rot)` inside `hasattr(rot, "w")` branches.
* **Pure BMesh Multi-Object Merging & In-Place Weight Transfer**: `MeshMergeEngine.consolidate_and_merge_meshes` operates as a pure BMesh pipeline (without relying on `bpy.ops.object.join()` or UI selection state), requiring explicit `blend_data` injection. It safely transfers vertex weights across differing vertex group indices by name, automatically creates target groups if missing, and transforms vertices by their world matrices before merging into a target mesh.
* **`core.compat.Vector` NamedTuple Immutability**: In standalone environments without `mathutils`, `core.compat.Vector` is implemented as a `NamedTuple`. Modifying components in-place (`v.x += dx` or `v.co -= offset`) raises `AttributeError: property 'x' of 'Vector' object has no setter`. Standalone test doubles and mock vertices simulating keyframe handles or vertex translations must use mutable 3D vector doubles (`MockVec3`) rather than the immutable fallback tuple.
* **BMesh Mock Container Traps (`ensure_lookup_table` & `layers.deform`)**: In headless unit tests, `bmesh.from_mesh()` and deform weight queries expect `.verts`, `.edges`, `.faces` collections that support `.ensure_lookup_table()`, `.index_update()`, and `.layers.deform`. Simulating these collections with raw Python lists (`[]`) causes immediate `AttributeError`. Test mocks must wrap vertex/face sequences in containers providing these lookup and deform layer protocols.

## 5. Headless CLI, Subprocess & Memory Management

* **Cross-Platform Headless Subprocess / Worker Execution (`cmd.exe` vs `sys.executable`)**: Spawning background worker processes or mock CLI handlers using Windows-specific shells (`["cmd.exe", "/c", ...]`) fails immediately on Linux CI runners with `FileNotFoundError: [Errno 2] No such file or directory: 'cmd.exe'`. Cross-platform test harnesses, worker simulations, and batch subprocesses must invoke `[sys.executable, "-c", "..."]` or platform-agnostic commands directly.
* **Blender Headless `--python-exit-code 1`**: Blender headless (`blender -b`) exits with code `0` even when unhandled exceptions occur or unittests fail. CI pipelines and verification scripts must explicitly supply `--python-exit-code 1`.
* **Headless Subprocess CLI Argument Parsing Trap (`--` delimiter)**: When launching headless Blender with `--python script.py -- [args]`, Python's `argparse.parse_known_args()` terminates option parsing upon encountering `--`. All subsequent arguments are placed into the `unknown` vector. Scripts expecting CLI arguments inside Blender must explicitly slice `argv = sys.argv[sys.argv.index("--") + 1:]` prior to invoking `parser.parse_known_args(argv)`. Failure to slice `sys.argv` causes CLI flags to be missed, causing scripts that re-invoke Blender to enter infinite recursive fork loops.
* **Working Directory `sys.path` Resolution under `--factory-startup`**: Headless Blender instances launched with `--factory-startup` do not automatically register the repository working directory in Python's `sys.path`. Subprocess scripts executed via `--python` must programmatically determine the repository root (`os.path.dirname(os.path.dirname(os.path.abspath(__file__)))`) and inject it into `sys.path` before attempting to import repository packages.
* **Headless `bpy` Mocking Boundary & RNA Duck-Typing Ban**: Outside Blender, `bpy` is `None`. Standard Blender RNA objects (`Object`, `Mesh`, `Collection`, `Material`, `MaterialSlot`) always guarantee core attributes (`.type`, `.name`, `.data`, `.modifiers`, `.polygons`, `.loops`, `.users`, `.material_slots`). Production code must access these directly; defensive duck-typing checks such as `getattr(obj, "type", "") == "MESH"` or `getattr(mesh_data, "polygons", [])` are strictly prohibited mock-induced production smells. Mocks in `tests/conftest.py` must satisfy the full production RNA contract, not vice versa. Where headless mocks are unavoidable, use `MagicMock(spec=...)` / `create_autospec` against `fake-bpy-module` types so mocks reject non-existent attributes.
* **Blender `bpy_prop_collection` Membership Check in Mocks (`in` vs `.get()`)**: In Blender's C-API, `bpy_prop_collection` (e.g. `obj.vertex_groups`) implements `__contains__`. However, in headless unit tests using `MagicMock`, `"group_name" in mock_obj.vertex_groups` evaluates `mock_obj.vertex_groups.__contains__`, which defaults to `False` on unconfigured mocks. Prefer the native idiomatic query `vg = obj.vertex_groups.get(group_name); if vg: ...` instead of `in` or defensive duck-typing checks.
* **Mock Matrix `@` MatMul Chaining & `.decompose()` Trap**: In standalone headless tests without `mathutils.Matrix`, matrix multiplication `inv @ mat` produces a new `MagicMock` by default. If downstream code calls `.decompose()` on the product, the unconfigured mock returns an empty mock instead of a 3-tuple `(loc, rot, scale)`, raising `ValueError: not enough values to unpack (expected 3, got 0)`. Mocks participating in matrix transformations must explicitly configure `mock_mat.__matmul__.return_value = mock_mat` or provide a valid tuple return for `mock_mat.decompose.return_value`.
* **Embedded Blender Python in Headless CI / Test Environments**: Official standalone Blender distributions and tarballs do not bundle `pytest` or external test fixtures in their embedded Python environment. In-Blender test runners executed under `blender -b --python ...` must guard `import pytest` with `try...except ImportError` (falling back to standard library `unittest`) or explicitly inject external `site-packages` into `sys.path`.
* **Draw Callback Restriction**: Writing to Blender RNA/DNA properties inside `draw_handler_add` raises `RuntimeError: Operator or data manipulation during draw callback is forbidden`. Draw handlers must remain strictly read-only.
* **Zero Undo Pollution**: Modal simulation loops must omit `{'UNDO'}` from `bl_options` to keep user `Ctrl+Z` history clean.
* **Differential Visibility Sets**: Only call `obj.hide_set()` if `obj.hide_get()` differs from the target state to avoid rebuilding the depsgraph every frame.
* **Blender Native Image Buffer Deallocation (`buffers_free`)**: `img.pixels.foreach_get(buf)` caches native unmanaged memory in C++. Free explicitly via `if hasattr(img, "buffers_free"): img.buffers_free()` inside `finally` blocks.
* **Global Undo & Memory Leaks in Batch Runs**: Multi-asset batch processing retains undo modifier history in RAM. Wrap in `use_global_undo = False` and invoke `bpy.data.orphans_purge(...)` + `gc.collect()` + OS heap compaction (`ctypes.cdll.msvcrt._heapmin()` on Win32 / `malloc_trim(0)` on Linux).
* **Async Texture Worker Safety**: Blender's Python `bpy` C-API is not thread-safe. Worker threads in `ThreadPoolExecutor` must receive pre-quantized NumPy arrays / PIL images and file paths only (zero `bpy` calls on workers). Enforce a synchronous join barrier (`wait_all()`) before package export.
* **Blender MCP Socket Server (Port 9876)**: The `blender-mcp` toolserver requires Siddharth Ahuja's TCP JSON socket server on `127.0.0.1:9876` (`blender_mcp.py`). Campbell Barton's official extension (`bl_ext.blender_org.mcp`) uses stdio and will reject port 9876 connections.

## 6. Texture Baking & Impostor Invariants

* **Octahedral Normal Baking Invariant**: Octahedral atlas normals must be rendered via camera-orbit animation frames (1..64) in an isolated unlit scene (`bpy.ops.render.render(animation=True)`). Neutral surface-facing normal is $(0.5, 0.5, 1.0)$.
* **Zenith Pole Singularity & Dynamic Up-Vector**: At zenith $(0, 0, 1)$, naive camera tracking collapses into a zero vector and causes $180^\circ$ highlight flipping. The camera coordinate basis must dynamically switch its reference up-vector from $(0, 0, 1)$ to $(0, 1, 0)$ when $|\text{Forward}_z| \ge 0.999$.
* **Single-Card Impostor UV Island Packing Hazard**: `bpy.ops.uv.pack_islands()` displaces normalized $[0, 1]^2$ UV bounds on single-card octahedral proxy meshes. Single-card and octahedral meshes must be strictly excluded from automatic island packing.
* **Fillrate Overdraw Cutout Octagons**: Bounding sphere quads leave $> 80\%$ transparent pixels on slender assets. Beveling quad corners by $25\%$ yields an 8-vertex convex polygon that cuts transparent fillrate overdraw by $30\text{--}40\%$.
* **Windows UNC `//` NetBIOS Freeze Trap on Unsaved Scenes**: In unsaved scenes (`filepath == ""`), relative paths starting with `"//"` evaluate as Windows UNC network paths (`\\Textures`), triggering a 30-second NetBIOS timeout before `[WinError 53]`. Unsaved relative paths must anchor to `tempfile.gettempdir()`.
* **Blender 5.x `colorspace_settings` ImBuf Reset**: Assigning `image.colorspace_settings.name = "Non-Color"` in Blender 5.x invalidates and zeroes any unsaved in-memory float pixel buffer (`ImBuf`). Always set `colorspace_settings.name` *before* calling `image.pixels.foreach_set(...)`, and never reassign it afterward in material setup helpers.
* **Blender C-API `img.pixels` Scanline Inversion & Bottom-Up Orientation**: Blender's `bpy.types.Image.pixels` buffer is ordered bottom-to-top (`row 0` = South / $Y_{\min}$ / $V = 0.0$, `row res_y - 1` = North / $Y_{\max}$ / $V = 1.0$). Standard PNG encoders write top-down ($Y=0$ at top). Without vertical array reversal (`np.ascontiguousarray(arr.reshape((h, w, 4))[::-1]...)`), baked tiles are vertically inverted, corrupting UV sampling. Conversely, when generating procedural heightmaps or coordinate grids, indexing rows from $Y_{\min}$ maps 1:1 to UV coordinates without flipping.
* **Camera-Space Normal Mapping Z-Sign Invariant**: Blender camera forward is $-Z$ in camera space ($Z_{\text{cam}} = -1.0$ for camera-facing surfaces). To map to tangent space $+Z$ (flat blue $(0.5, 0.5, 1.0)$), the Z scale factor in the unlit emission override must be $-0.5$ (`(0.5, -0.5, -0.5)` for UE5 DirectX, `(0.5, 0.5, -0.5)` for OpenGL). Using $+0.5$ produces $Z \le 0.0$ (pitch black normals).
* **Billboard Perspective Fanning vs Uniform View Vector**: Per-fragment `Geometry.Incoming` on billboard proxy quads causes perspective fanning across large quads at close distance, crossing octahedral tile thresholds and causing seams across the asset face. Shaders must compute a uniform view vector: `normalize(CamWorldPos - ObjWorldPos)` via `ShaderNodeVectorTransform(POINT, CAMERA/OBJECT -> WORLD)`.
* **Decoupled Billboard Tracking Target vs F-Curve Animation Overwrite**: Billboard `TRACK_TO` targeting a camera with turntable keyframes causes depsgraph F-curve evaluation to clobber camera position updates during interactive navigation. The billboard constraint must target an Empty (`Preview_Tracker_Target`) driven by an epsilon-gated background timer (`bpy.app.timers`) at $10^{-4}$ threshold.
